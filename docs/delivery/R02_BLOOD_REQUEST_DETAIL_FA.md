# R02 — جزئیات و تصمیم درخواست خون
مبنا: Integration e0b4f4be (PR20، 116/116). از RequestDetailComponent موجود استفاده می‌شود؛ بدون AuthService مستقل، API جدید یا تغییر زیرساخت.
## مسیرها
- /hemo/requests/detail/:guid: Guard اصلی + detail؛ ارسال/لغو فقط مالک و وضعیت مجاز؛ تصمیم فقط decide و AwaitingDoctor؛ تأیید با نظر صریح پزشک و نسخه جاری، بدون پذیرش تغییرکرده.
- /hemo/requests/bank/:guid: Guard اصلی + bankDetail؛ تنها GET Bank، بدون عملیات تصمیم یا صدور.
- لینک‌های صفحات هنوز متصل‌نشده (ویرایش، پذیرش از این صفحه، بانک و انتقال) موقتاً حذف شده‌اند؛ به تدریج با Seed و Route متناظر برمی‌گردند.
- تغییر شناسه در همان route، تغییر نقش/نشست و destroy: داده قدیمی، پاسخ دیرهنگام و چاپ نامعتبر کنترل می‌شوند. نمایش پیام موفقیت از query string حذف شد.
## کاربر
از فهرست یا کارتابل، جزئیات را باز کنید. پزشک شرح و شماره نظام پزشکی و تأیید صریح وارد می‌کند؛ رد یا برگشت به دلیل نیاز دارد. این ثبت نرم‌افزاری است، نه امضای دیجیتال قانونی یا تأیید بالینی سازگاری.
## تحویل
۴ تست جدید component/HTTP و به‌روزرسانی تست route و لینک. CI هنوز تأیید نشده. Seed متناظر detail و bank detail باید پیش از عرضه فعال شود؛ فرم پرستاری/پزشک و edit در slice بعدی. بدون حساب جدید.
