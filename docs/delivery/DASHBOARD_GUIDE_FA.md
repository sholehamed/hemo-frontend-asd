# ST-09 | داشبورد نقش سازمانی
ورود به /home برای همه نقش‌های مجاز. تغییر نقش از انتخابگر بالای صفحه، بارگذاری مجدد و کشف مجوزهای نقش جاری را انجام می‌دهد. لینک‌های ماژول‌های پیشین باقی هستند.
## راهنمای کاربران
| حساب | میز کار |
|---|---|
| hemo.admission | پذیرش، تطبیق، سوابق و کنترل ترخیص |
| hemo.supervisor | پذیرش و مغایرت هویت؛ عملیات مطابق مجوز |
| hemo.viewer | شاخص‌های پذیرش و گزارش، بدون ایجاد |

نمایش کارت‌ها و اقدامات بر اساس Capability واقعی، نه متن نام نقش. عدد هشدار رنگی بیانگر شمارش رکورد نیازمند بررسی است، نه تعیین خطر بالینی یا توصیه درمانی. کلیک مشاهده رکوردها فقط برای فیلتر متناظر و مجوز List انجام می‌شود؛ کارت فاقد لینک را از گزارش ماژول بررسی کنید. آمار مرکز لزوماً کارتابل شخصی نیست؛ شمارش درخواست پرستار با mine=true محدود به خودش است.
دکمه دریافت مقایسه دو هفته کامل UTC پیش از امروز را برای پذیرش، واکنش و کیفیت (در صورت مجوز) بارگذاری می‌کند. شروع تزریق با تاریخ شروع و واکنش با تاریخ بروز شمارش می‌شود؛ مقایسه تعداد نرخ عوارض نیست. شاخص‌های کیفیت اصلی ۳۰ روز اخیرند. خطای هر منبع مستقل نمایش داده می‌شود و با صفر جایگزین نمی‌شود. خروجی CSV از شاخص‌های بارگذاری‌شده و مقایسه، بدون رکورد فردی است.
## راهنمای توسعه‌دهنده
HomeComponent از سرویس‌های موجود Admission, BloodRequest, BloodBank, Transfusion, Hemovigilance, HemoQuality استفاده می‌کند؛ endpoint و schema جدیدی لازم نیست. درخواست آمار فقط با مجوز stats مربوطه؛ کنترل نهایی مجوز و مرکز در handler سرور است. Promiseهای هر بخش مستقل مدیریت می‌شوند. فیلترهای ورودی URL در لیست‌های متناظر با allowlist بررسی می‌شوند؛ مجوز دسترسی از URL گرفته نمی‌شود. فیلترهای بانکی که دقیقاً با aggregate یکسان نیستند لینک مستقیم شمارش ندارند. مدل fullWeeks بازه‌های غیرهمپوشان تعریف می‌کند؛ آزمون dashboard-model و Playwright داشبورد را پوشش می‌دهند. تست‌های Playwright با API fixture هستند.
## محدودیت‌ها
تاریخچه موجودی و روند زمانی همه شاخص‌ها در API موجود ارائه نشده؛ از snapshot فعلی تاریخچه مصنوعی ساخته نشده. شمارش گروه‌های مختلف روی هم جمع نمی‌شود. داشبورد مدیریت تجمیع مرکز جاری است، نه سازمان چندمرکزی. Seed تاریخی فقط برای پذیرش است، نه شواهد بالینی. طرح بصری در مرورگر واقعی شرکت و با کاربر نهایی نیاز به UAT دارد.
