## استفاده مجدد از اجزا
AdmissionPicker برای انتخاب بیمار از پذیرش موجود (در صورت اعطای مجوز خواندن)، RequestState برای خطا/بارگذاری، Jalali date utilities، الگوی جدول و pagination موجود و Angular Material. محصول/تعداد، داده بالینی شرطی و کارت خلاصه درخواست به عنوان کامپوننت‌های مشترک جدید ساخته می‌شوند.

## روند و کنترل‌ها
- انتخاب پذیرش موجود؛ نمایش اطلاعات هویتی از سرور، بدون ثبت مستقل نام و شناسه بیمار.
- انتخاب نوع فرم، اقلام، تعداد و ثبت داده‌های بالینی؛ ذخیره پیش‌نویس، بازبینی، ارسال برای پزشک.
- پزشک درخواست ارسال‌شده را بررسی و تأیید/رد/برگشت را صریح ثبت می‌کند. دلیل رد/برگشت اجباری. درخواست در صف بانک خون نشان‌دهنده صدور یا سازگاری نیست.
- نقش‌ها و قابلیت‌ها از Backend دریافت می‌شوند؛ UI جایگزین مجوز API نیست.
- اتصال API، فرم‌های تخصصی و ویزارد، کارتابل پزشک، آمار و تست گردش کامل در اسلایس‌های بعدی ST-03.
- فایل blood-request-model.ts کدهای اولیه، وضعیت‌ها و قواعد ساختاری اقلام را تعریف می‌کند. در این کامیت هیچ فراخوانی API فرضی یا داده ساختگی به محیط اصلی اضافه نشده است.
